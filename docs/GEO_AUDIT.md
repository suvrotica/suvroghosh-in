# GEO Audit — suvroghosh.in

Baseline audit of conventional-search and generative-search discoverability, performed on branch
`feat/geo-discoverability` against a production build (`npm run build`) served locally with
`npm run preview`. Evidence comes from the final server-rendered HTML of representative routes, not
only Svelte source.

## Crawler policy decision (deferred, documented)

`robots.txt` currently permits all crawlers, including AI training crawlers such as GPTBot and CCBot,
and AI search crawlers such as OAI-SearchBot and PerplexityBot. Whether to allow model-training
crawlers is a content-policy decision for the site owner, not an engineering decision. This branch
**preserves the present permissive behaviour unchanged**. If the owner later decides to disallow
training crawlers while retaining search crawlers, the change belongs in `static/robots.txt` and
should target `GPTBot` (training) separately from `OAI-SearchBot` (search), and `Google-Extended`
separately from `Googlebot`.

## Summary

The site's technical SEO foundation is stronger than the brief suspected: SSR content, canonical
redirects, per-article OG/Twitter metadata, BlogPosting and BreadcrumbList JSON-LD, an accurate
sitemap, RSS autodiscovery, and a sitemap-declaring robots.txt are all already in place. The genuine
gaps are (1) structured data is not yet one coherent entity graph with a shared WebSite `@id`
present on every page, (2) visible FAQ blocks have no FAQPage counterpart, (3) `dateModified` is
supported but unused, (4) hard-coded static-page `lastmod` values can drift, and (5) there is no
build-time validator for rendered JSON-LD, orphan posts, or sitemap/canonical agreement. The
implementation phases below address exactly these.
