# 30/60/90-day measurement and remediation plan

Audit baseline date: **2026-08-06 (Asia/Calcutta)**

Day 0: the date the owner starts the plan; record it in the private decision log

## Outcome

The first 90 days are for replacing unknowns with trustworthy measurements, improving a very small set of evidence-ready pages, and testing whether search visibility, authority, distribution, performance, or conversion is actually limiting outcomes. The plan does not promise a traffic number and does not use “publish more” as the default remedy.

All external account, DNS/mail, provider, editorial, identity, and distribution actions are owner-only. No automated outreach, mass submission, mass reindexing, mass editorial change, or unreviewed production setting change is part of this plan.

## Measurement contract

- Use Asia/Calcutta-labelled windows and preserve exact start/end times.
- Keep Google, Bing, Vercel, channel analytics, and enquiries in their native counting units. A visitor, page view, search click, action, and person are not interchangeable.
- Freeze the 25-page provisional flagship cohort only after owner editorial approval. Record cohort changes instead of rewriting the denominator retrospectively.
- Annotate owner tests, deployments, monitoring, preview traffic, synthetic checks, and the known 2026-08-06 audit-contamination interval. Reject a comparison window when contamination cannot be bounded.
- Compare like with like: same environment, hostname/canonical mapping, timezone, route/device segment, window length, event definition, and tool retention.
- Keep private exports and people-level records out of the repository. Public scorecards contain aggregate counts and sanitized statuses only.
- A missing value is `UNVERIFIED`, `NOT ESTABLISHED`, or `INSUFFICIENT DATA`; it is never silently converted to zero.

## Days 0–30 — Establish truth and readiness

### Required work

1. Execute OA-01 and OA-02 in [OWNER_ACTIONS.md](./OWNER_ACTIONS.md): obtain authenticated Google/Bing evidence, including Manual Actions, Security Issues, indexing, sitemaps, search performance, links, Core Web Vitals, Bing security, and IndexNow Insights. Do not change ownership/DNS unless the owner explicitly approves the verification method.
2. Freeze the measurement contract above. Choose no more than two legitimate outcome events, approve privacy boundaries, and begin a clean 30-day window with owner/test/deploy/synthetic annotations.
3. Treat all post-audit analytics on 2026-08-06 as potentially contaminated unless the platform proves otherwise. Do not delete or rewrite the recorded series.
4. Use the accepted crawl gate: 1,022 reconciled URLs; 933 strictly eligible canonical graph URLs; one connected 935-node rendered graph; zero true or crawler-unreachable orphans; 59 near-orphans; two notebook dead ends; 218 pagination-only canonicals; one visible-unreachable inactive-tab resource; and 25/25 technically eligible, contextually linked, hub-supported flagships. Keep engine indexing separate and unverified.
5. Approve one healthcare and one interactive flagship at most for the first cycle. Map consequential claims to primary/institutional evidence, document author contribution and limitations, verify canonical/initial HTML, and require performance/accessibility readiness. An essay may use a separate literary/newsletter path without commercial rewriting.
6. Select the first measured performance correction from the finalized route evidence. Preserve the before SHA and require telemetry-blocked lab tests.
7. Begin DMARC Stage 0/1 only: inventory every legitimate sender and prove SPF/DKIM/alignment using consented, sanitized headers. Make no DMARC DNS change yet unless this prerequisite is complete.
8. Close authorized VirusTotal, URLhaus, SmartScreen, provider-log, social-inspector, and subdomain-inventory evidence gaps. Do not publish a post or request delisting without a verified positive.
9. Triage dependency, notebook, contact, and optional TTS findings into isolated implementation proposals. Do not mix these changes with SEO/content work.

### Day-30 exit gate

- Search-console access is resolved or remains explicitly blocked with a named owner/dependency.
- The metric dictionary, cohort, filters, event definitions, privacy boundary, and contamination log are frozen.
- The first clean window is in progress; no contaminated value is labelled human or organic.
- Each first-cycle flagship has a signed-off evidence/readiness decision.
- The selected performance change has a comparable pre-change baseline.
- The sender inventory and alignment matrix are complete before any enforcement policy.
- Every crawl/performance issue used for action links to its exact report row; unavailable engine/account counts remain explicitly unverified.

## Days 31–60 — Execute narrow fixes and one manual cycle

### Required work

1. Complete the first clean 28-day scorecard for every metric whose source is available. Preserve `UNVERIFIED`, `NOT ESTABLISHED`, or `INSUFFICIENT DATA` for the rest.
2. Reconcile search impressions/clicks with Vercel directionally by date and canonical landing page. Explain rather than erase differences in units, consent, attribution, and bot handling.
3. Fix only approved exact crawl-derived targets: two missing-canonical notebook dead ends, two page-2 canonical/title conflicts, one hidden-only resource path if it remains public, and two shared legacy topic hrefs. Consider one shallow contextual path for the sole depth-four flagship only after editorial review. Re-run the bounded crawl and compare source, sitemap, canonical, live URL, initial HTML, redirects, and internal-link depth; do not mass-remove, merge, redirect, noindex, link, or request indexing.
4. Ship the first route-specific performance change only after narrow and repository-wide validation. Compare telemetry-blocked lab results immediately; begin a stable same-route/device field observation window.
5. After owner approval, complete evidence and accessibility/static-fallback work for at most two first-cycle flagships. Use the site journeys deliberately: professional pages may route to relevant résumé/consulting/contact surfaces; literary work should not receive generic commercial blocks.
6. Run one owner-executed six-week distribution cycle: one useful native owned-channel item per ready page, then at most five carefully selected, rules-compatible community/curator/editor contributions. No automated outreach and no request for a backlink as the primary exchange.
7. If every legitimate sender is aligned, publish an owner-approved `p=none` DMARC monitoring policy with a private aggregate-report destination. Validate after propagation and observe for at least two to four weeks or a complete sending cycle.
8. Implement accepted security fixes in separate reviewed branches, with their prescribed tests and production verification. Keep DNSSEC/CAA and broad header changes deferred until host/provider compatibility is complete.

### Day-60 exit gate

- A clean 28-day traffic estimate exists, or the measurement product's inability to produce one is documented and a privacy-reviewed replacement decision is recorded.
- Google/Bing page/query/index/link baselines exist where access permits; no public `site:` count substitutes for them.
- Before/after crawl and lab comparisons show whether each narrow fix preserved canonicals, initial content, semantics, and accessibility.
- Distribution records identify page, channel, date, placement type, canonical URL, and aggregate result without people-level data.
- DMARC remains monitoring-only until its alignment and legitimate-delivery gates are proven.

## Days 61–90 — Decide from evidence, then scale selectively

### Required work

1. Compare the same frozen cohort and metric definitions to the Day-30/Day-60 baselines. Do not retroactively exclude poor results or recast unknown referrers as direct readers.
2. Classify flagship outcomes by failure layer: technically ineligible, not indexed, no impressions, weak position, low CTR, clicks without continuation, or qualified outcome. Choose the next correction at the earliest demonstrated failing layer.
3. Review field performance only after a stable same-route/device window. Keep improvements that hold without accessibility/content regressions; roll back or revise changes that shift cost or break behavior.
4. Continue a distribution track only when it produces attributable use, genuine editorial/community reference, qualified continuation, or useful feedback. Otherwise revise the asset/audience or stop. Do not compensate by increasing outreach volume.
5. Consider a second two-page flagship cycle only after the first passes its evidence, performance, measurement, and channel-rule gates.
6. Review the 205 content-remediation candidates with search/query and editorial evidence. Consolidate, redirect, noindex, or materially rewrite only a page pair/group whose audience intent and canonical replacement are genuinely equivalent. Preserve fiction, satire, essays, and personal records where their archival/literary job is valid.
7. Advance DMARC to a limited quarantine percentage only if all legitimate senders remain aligned and monitoring shows no legitimate loss. Do not advance to reject merely because Day 90 arrived.
8. Re-run the complete validation/crawl/build suite after approved implementations and record exact outcomes. Recheck provider/security verdicts only at a justified cadence; do not repeatedly rescan or submit.

### Day-90 decision gate

Produce one sanitized scorecard using the table above and answer:

- Is the clean human estimate now trustworthy, and what uncertainty remains?
- Are the flagships indexed and receiving impressions; if so, is the constraint position, CTR, continuation, or outcome?
- Did any earned referring domain or qualified referral appear, and is it independent rather than owned?
- Did résumé/contact actions and substantive enquiries occur under the frozen definitions?
- Did loading performance improve without semantic, accessibility, interaction, layout, or content regression?
- Which page/evidence/distribution work produced attributable value, and which should stop?
- Which security, reputation, provider, and mail states are verified, still unverified, or require remediation?

The next 90-day plan should follow those answers. It must not promise traffic, default to publishing more articles, or scale distribution merely because activity is easy to count.

## Decision rules by observed failure layer

| Observed evidence                                                | Next action                                                                                         | Do not do                                                                |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| URL technically ineligible or canonical/indexing defect verified | Correct the exact technical defect, validate, then allow recrawl                                    | Rewrite content or buy links before eligibility is restored              |
| Eligible but not indexed in account-level evidence               | Inspect coverage/canonical/crawl causes and representative URLs                                     | Mass-request indexing or assume IndexNow guarantees inclusion            |
| Indexed with no meaningful impressions                           | Reassess demand, audience wording, page job, evidence, and internal discovery                       | Treat every literary/archive page as an SEO failure                      |
| Impressions with weak position                                   | Improve substantive evidence, usefulness, entity clarity, internal paths, and legitimate references | Manufacture keyword volume, schema, FAQs, or backlinks                   |
| Meaningful impressions and position but weak CTR                 | Test an accurate title/deck/snippet on the specific page                                            | Use clickbait or change every title at once                              |
| Clicks without qualified continuation                            | Clarify the journey and one relevant next action; verify performance and event health               | Call bounce a content failure while traffic remains contaminated         |
| Qualified use but no substantive outcome                         | Review offer, proof, friction, and form reliability with privacy-safe evidence                      | Add indiscriminate CTAs to essays or count intent as success             |
| Manual/security issue or verified listing                        | Preserve evidence, fix the root cause, use the exact service review route                           | Generalize one listing to every search, browser, email, or social system |

## Reporting cadence

- **Weekly:** annotation log, deployments, synthetic checks, instrumentation changes, security/provider alerts, and unusual route/geography bursts.
- **Every 28 days:** clean analytics estimate, engine page/query performance, indexed flagship count, earned-domain classification, qualified route/action funnel, and route/device field performance.
- **At each six-week cycle:** flagship evidence/readiness review and manual distribution result.
- **At policy milestones:** sender alignment, DMARC aggregate summary, legitimate-delivery check, and rollback readiness.
- **At Day 90:** complete scorecard, decision log, accepted/rejected hypotheses, before/after validation, and the next bounded work queue.
