# The Six-Week Shadow

## Concept and physical mapping (written before geometry)

The ordinary object is a fictional desk lamp. Its button moves a small distance; the obligations extend a much greater distance. A fitted foldout drawing desk keeps the lamp at a constant size. Beside it, a semantic time ruler measures elapsed working days at one unchanging scale. Solid work tiles and inset, slotted wait tiles distinguish occupied work from elapsed waiting. The ruler is deliberately not a simulated light shadow.

The revised base sits on a sample bench. A slatted crate behind a booking stop represents the supplier slot. A small clamping fixture represents revised production. Three physical document cards represent the parallel instruction, photograph and packing-reference work; a fourth is the support card. They have their own shelf beside the chain rather than extending its length. A packing insert and released parcel finish the bounded stage. All physical areas have matching keyboard-accessible HTML task controls.

## Model and state boundary

`model.ts` owns validated settings, fictional task records, stable topological scheduling, elapsed completion, effort and controlling path. Roots start at zero; a task waits for its latest prerequisite. Separate people are assumed for I and J; this is not resource levelling. `url-state.ts` permits only five bounded versioned settings. The UI owns inspection, guide beat and compressed replay time independently of those inputs. Work/Waiting/All changes visual emphasis only.

The no-change state means no change project is proposed. It makes no claim about the existing manufacturing business. The ten-minute drawing suggestion is contained in task A's first day. Thirty days is the default fictional batch scenario, never an industry benchmark. Weekends, public holidays, existing backlog outside the two waits, rework, compliance and actual supplier performance are excluded. This is not electrical modification guidance.

## Verification contract

The feature unit suite is included by the repository Vitest configuration. Six tests passed for default and zero-wait results, parallel branch control, deterministic ties, graph rejection, bounds and URL state. Focused ESLint passed. The authoring generator records the real solid shape for every rendered solid and uses the existing vendored audit. An actual `--audit` run passed with zero reported problems: 106 solids, five states (0, ¼, ½, ¾, 1), 1,660 overlaps and 332 solved depth rules. Grounding applies only to the four real feet; no proxy shape or clearance exclusion was used. Line-end audits on both generated theme previews reported zero floating ends and clean consoles.

Development-browser captures at 1,440 and 390 pixels were visually inspected, with reduced motion enabled and service workers blocked. Both reported no page errors and no horizontal overflow. The phone version uses a large centred lamp, the same fixed 0–50-day ruler and a vertical HTML task journey; selecting a task brings that assembly forward from the same generated geometry. These are development checks, not a claim of production-preview completion.
